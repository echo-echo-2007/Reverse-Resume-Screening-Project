## 职位广场（`/`）

### 2026-11-20
- **筛选不再「跳到左上角」**。原因：以前每次筛选都把列表整块换成一行居中的「加载中…」，页面高度瞬间塌下去，浏览器会把滚动位置夹回去，看起来就是内容突然跳到顶部左上角。
  现在：首次进入用骨架卡占位；再次筛选**保留旧列表**（半透明 + 禁点），只在统计行显示「筛选中…」，页面高度和滚动位置都不动，结果就地在原处换成新列表。
- **统计文案跟着筛选走**：未筛选「共 4 个在招职位」，筛选后「共 3 个符合条件职位」，不再一律写「在招」。
- **补「重试」**：接口失败时错误条里可以直接点重试，不用手动刷新整页；失败时旧列表不再被清空。
- **数据**：清掉测试公司名尾部的数字。例如「初筛测试公司454111 → 初筛测试公司」「测试公司66057517 → 测试公司甲」「别家公司454111 → 别家公司乙」，职位「无城市职位454111 → 无城市职位」。
  原因：早期注册脚本为了不重名，把手机号后 6 位拼进了公司全称，属于测试数据，不是界面多渲染了 ID。

### 2026-11-21
- **筛选结果不再滚动**：去掉上一版「结果回来后平滑滚回列表开头」的处理，改成原地替换，用户在哪就在哪看到新结果。
- **列表视觉重做**：
  - 左边加公司首字母方块（淡橙渐变 + 淡橙描边），一眼能区分不同企业
  - 公司行补上行业灰标签（如「互联网」），和「部门」用 `·` 分隔
  - 底部单独一行：左边「今天发布 / 昨天发布 / 11-13 发布」，右边「查看详情 →」，用细分割线隔开
  - 鼠标悬停整卡上浮 2px、描边变淡橙、投影用淡橙色（不再是灰投影）
  - 宽屏（≥1024）两列、窄屏单列；标签改为浅底 + 细描边，城市用主题橙、其余灰色
- **筛选栏**：选中的下拉框变淡橙底 + 加粗文字（一眼看出哪些条件生效），「清空筛选」改成悬停浅底按钮，整条筛选卡加细投影。
- **标题区**：标题前加淡橙竖条，右侧标注「按发布时间排序」（后端就是按 `created_at` 倒序）。
- **骨架屏**按真实卡片结构画（头像块 + 两行文字 + 三个标签 + 底部行），高度与真实卡片一致（实测都是 171px），首次加载不会跳一下。
- **下拉筛选换成自绘菜单**（不再用原生 `<select>`）。现象：点开城市下拉，选项列表会飘到页面左上角、还会把视图带偏。
  原因：原生 `<select>` 的弹出层由浏览器自己画，位置和滚动都不受页面 CSS 控制，页面一有缩放或嵌在预览里就对不上按钮。
  现在改成自绘：面板 `absolute` 挂在按钮正下方（间距 6px、左边缘对齐、宽度与按钮一致），不占文档流，所以展开、收起都不会推动下方列表，`scrollY` 和文档高度完全不变（实测展开前后都是 23px）；选中项打勾 + 淡橙底，箭头跟着翻转；支持 ↑/↓/Home/End/Enter/Esc，点外部或页面滚动自动收起；面板高度上限 `min(21rem, 55vh)` + `overscroll-contain`，城市 9 项一次看完，也不会滚着滚着把页面带走。
- **修**：学历筛选第一项原本显示「高中及以下及以上」，改为「高中及以上」。
- **三个筛选按钮统一 144px 宽**：换选项时按钮宽度不变，这一排控件不会被文字长度挤动。

## 我的简历（`/my/resume`）

### 2026-11-19
- 新页面：基本信息 / 教育背景 / 工作经历 / 自我评价四个区块，共 10 个字段，对应设计说明 1.3。
- `PUT /api/resume` 是整份覆盖，所以每次提交都把 10 个字段全传，空值显式传 `null`，避免「只改一项把别的项清空」这类事故。
- **工作年限只填「年」**（可填 2.5），提交时 `work_months = 年 × 12`；回填时再 ÷12 显示。这样库里仍是月口径，后端初筛逻辑一行都不用改。
- 校验：姓名必填 ≤64、手机号 `1[3-9]` 开头 11 位、邮箱格式、学历必选、毕业年份 1900–2036、工作年限 0–60；不通过只在字段下飘红字，**不发请求**。
- 未保存拦截：关标签/刷新走浏览器默认确认；点顶部导航等站内链接弹「有未保存的修改，确定离开？」。
- 新用户 `GET /api/resume` 返回 404 不算错误：空表单 + 姓名、手机号用账号信息预填。

### 2026-11-20
- **修正「上次保存」时间显示**。此前误判成接口多加了 8 小时，用 UTC 取位显示，结果比真实时间早 8 小时。实测库里存的就是 UTC（本地 22:53 保存 → 库里 `14:53:38`），接口带 `Z` 返回，前端直接用 `new Date()` 的本地时间才对。
- 时间格式化统一到 `constants.js` 的 `formatDateTimeShort()`（`MM-DD HH:mm`，本地时区），简历页与投递页共用一份。

### 2026-11-21
- **「期望城市」「最高学历」换成和筛选栏同一套下拉**（`SelectMenu`，`variant="field"`）：外观对齐输入框（同高 38px、同宽、同圆角描边），空值时文字灰（「不限」「请选择」），选中后是正常深色文字，不做筛选栏那种橙底——表单里每一项本来就是「选中态」，再标色反而吵。
- **踩到的坑**：`Field` 用 `<label>` 包控件，点下拉里的选项时，浏览器会把这次点击再转发给按钮，等于选完立刻又打开一次；而且这个默认行为 `preventDefault()` 拦不住。现在 `Field` 加了 `as` 参数，控件是 button 时传 `as="div"`，不再用 label 包。

## HR 工作台（`/hr`）与投递管理（`/hr/applications`）

### 2026-11-22
- **先搭骨架，功能待细化**：工作台、职位表单、投递管理三个页面 + 简历抽屉已能跑通真实数据，视觉沿用求职者端（白卡 + 淡橙主色）。
- 新增后端 `server/src/hr.js`：`GET /api/hr/overview`（5 个统计数字 + 本企业职位，2 次查询）、`GET /api/hr/applications`（跨职位列表 + 职位下拉选项，一次返回）、`GET /api/hr/applications/:id`（抽屉详情，含工作经历/自评长文本）。`requireRole('hr')` 挂在路由前缀上，`company_id` 只从 token 取。
- 列表接口刻意不返回长文本，抽屉打开才取详情；列表 200 条封顶是临时措施，正式版换 cursor 分页。
- 拒绝做成抽屉内联表单（原因四选一 + 备注选填），未做二次确认；`hr_viewed_at`、初筛预览 `dry_run`、批量操作都留 TODO。
- 职位表单薪资填 K 存元、经验填年存月；编辑时反算回显。字段级校验和「改硬条件不会重算初筛」的提示还没做。

### 2026-11-22（第一档补完）
- **硬条件逐项对比**：抽屉里新增三行，学历 / 经验 / 城市各给「合格 / 不符 / 未比较」，并列出「要求 本科及以上 · 候选人 本科」。职位不限或候选人没填的一方按「未比较」处理，不误判成年红。详情接口为此补了 `city_code` 与 `expected_city_code`。
- **拒绝前二次确认 + 默认原因**：打开拒绝表单时，按第一个不满足的硬条件预选原因（学历 → 经验 → 城市，都对不上才选「其他」）；点「确认拒绝」弹 confirm，文案里带候选人姓名、原因和「不可撤销」。实测取消后状态仍是待初筛。
- **列表分页与排序**：`GET /hr/applications` 支持 `page / page_size / sort`，返回 `total`；`sort` 只开放投递时间正序/倒序，同秒投递用 `id` 兜底，保证翻页不重不漏。前端分页条与排序下拉全部写进 URL，改筛选自动回到第 1 页。
- **表单字段校验**：职位名称必填、部门 ≤64 字、薪资 0-1000K 且上限不低于下限、经验 0-60 年；提交时一次性标红并把第一个出错的字段滚到视口中间，改字段即清除该字段错误。保存成功回工作台并显示一条提示。
- **概览卡 0 值不可点**：数字为 0 或仍在加载时卡片置灰、无 hover，避免点进空列表。
- **修 `updated_at` 不更新**：`applications.updated_at` 缺 `@updatedAt`，改状态后一直停留在投递时间。加注解并 `prisma generate`；同时发现旧行是 MySQL 默认值写的本地时间、新写入是 UTC，两种口径混在一列，已一次性 `UPDATE applications SET updated_at = applied_at` 对齐（旧值本来也从未真正更新过，无信息损失）。
- **踩坑**：`type="number"` 带 `max` 时浏览器原生校验会先拦下提交，`onSubmit` 根本不触发，自绘的中文错误文案永远不出现。表单加 `noValidate` 统一交给 `validate()`。
- **踩坑（验证用）**：CDP 里 `window.confirm` 打开期间 `Runtime.evaluate` 不返回，脚本会卡死；要先发点击、再等 `Page.javascriptDialogOpening` 事件。

### 2026-11-22（一键初筛无反应）
- **现象**：点「一键初筛」完全没动静。原因：确认用的是 `window.confirm`，在内置预览面板这类受限 iframe 里，原生弹窗会被浏览器直接忽略并返回 `false`，等于永远点了「取消」。现在：新增 `components/ConfirmDialog.jsx` 自绘确认框（普通 DOM，样式统一，Esc/点遮罩可关，焦点默认在「取消」上，Tab 锁在弹窗内），一键初筛和拒绝投递都改用它，不再依赖浏览器原生弹窗。
- **现象（连带）**：初筛跑完后，结果提示条渲染在页面顶部；用户点的是列表下方的按钮，滚动位置靠上时看不到提示，依旧像「没反应」。现在：结果改成固定在视口右下角的提示条（成功 6 秒、失败 9 秒自动消失，可手动×掉），带「查看该职位投递」链接。
- **弹窗条件显示「不限/不限」**：`/hr/overview` 的职位字段白名单里没有 `min_education_level / min_experience_months`，前端拿到 `undefined` 就显示成「不限」。已补字段，并额外返回每职位 `pending_count`（第三次 groupBy，按 job_id 数 pending），初筛按钮直接显示待筛条数、为 0 时禁用，弹窗里也标明「N 条待初筛」。
- **拒绝备注只有等级数字**：初筛写入 `reject_note` 的内容从「学历不满足：职位要求 3，简历 2」改成「学历不满足：要求本科及以上，候选人为大专」「经验不满足：要求 2 年以上，候选人 10 个月」「城市不匹配：职位在北京，候选人期望上海」。为此初筛查询补了 `city_name` 与 `expected_city_name`。历史备注不会自动改写，只影响之后的初筛。

### 2026-11-23
- **拒绝理由留出独立位置**：原来一整行「已拒绝 · 其他（不合适）」，备注用括号挂在后面；备注一长就整行挤在一起，也容易被误读成原因的一部分。现在拆成三块：第一行「原因 + 阶段标签（系统初筛 / HR 操作）」，第二行备注单独一块（`whitespace-pre-line`，保留换行、自动折行），底部小字「处理于 MM-DD HH:mm」。
- **区块位置前移**：拒绝原因从抽屉最底部（自我评价之后）移到「硬条件对比」下方。原因：HR 打开抽屉最想知道的就是「为什么被拒」，原来要滚到最底才能看到，还会被 footer 压住。
- **拒绝确认弹窗同步拆分**：`确认拒绝` 的说明从「候选人 X，拒绝原因：其他（备注：不合适）」改成候选人一行 + 「拒绝原因 / 备注」两行标签，弹窗里也能看清备注原文。
- 详情接口补 `screened_at`，抽屉才能显示处理时间（原来只有 `applied_at` / `updated_at`）。

### 2026-11-23（初筛改为后台自动，HR 看不到被筛掉的人）
- **去掉 HR 的「一键初筛」按钮**（工作台职位行 + 确认弹窗一起删除，`POST /api/jobs/:id/screen` 接口下线，`api.screenJob` 同步移除）。
  原因：初筛是硬条件机械判定，没必要占用 HR 的注意力，也不该漏点——忘了点，不达标的人就一直堆在待处理里。
- **改由投递接口在写库前同步判定**：新增 `server/src/screening.js`（口径仍是 学历 → 经验 → 城市，命中第一条即停，城市任一方为空则跳过），`POST /api/jobs/:id/apply` 直接按结果写入——通过 = `pending`（进 HR 待处理队列），不通过 = `rejected` + `reject_stage='sql'`。判定和建记录在同一次写入里，不会出现「投递成功但没筛」的中间态。
- **被初筛拒掉的投递对 HR 完全不可见**：概览统计、投递列表、职位卡片的「投递 N 人」、简历抽屉详情全部过滤 `status='rejected' AND reject_stage='sql'`（详情接口直接返回 404，猜 id 也打不开）。过滤口径集中在 `visibleFromHr()` 一处，避免各接口各写一套漏掉。
  注意：只过滤**系统**拒的；HR 自己在抽屉里拒的（`reject_stage='manual'`）仍然保留在「已拒绝」里可查。
- **文案跟着改**：`pending` 从「待初筛」改为「待处理」（工作台统计卡、投递管理页签、状态徽章），职位行在「投递 N 人」旁加「待处理 N」小标签；职位表单硬条件说明改成「投递时由系统判定，不满足的直接过滤」；抽屉里那句提示改成「投递时已按 学历 → 经验 → 城市 自动初筛」。
- **求职者侧**：投递被自动拒掉时，「我的投递」里立刻就是「已拒绝」，抽屉里能看原因（学历不符 / 经验不足 / 城市不符）和系统备注，不会出现「一直没人看」的悬空状态。
- **数据**：存量 pending 用 `server/scripts/backfill-screening.js` 补跑一遍（run 过 `--dry` 再实跑）；测试账号张招聘名下 9 条 → 通过 2 条、拒绝 7 条。
- **工作台职位行去掉「投递管理」按钮**：同一行里「投递 N 人 / 待处理 N」已经是投递信息，再挂一个按钮等于和左侧导航的「投递管理」重复，还会把行撑得零碎。现在每行只留「编辑」，进投递统一走导航。

### 2026-11-23（统计与投递人数迁到投递管理）
- **工作台瘦身成「只管职位」**：5 个概览数字整块搬走，职位行上的「投递 N 人 / 待处理 N」也一并删掉。理由：工作台和投递管理各摊一份数字，哪边是准的都要想一下；候选人相关的信息只在一个地方看。现在每行只剩职位信息 + 「编辑」，行高从 98px 收到 68px。副标题改成「这里管理本企业的职位；候选人进度与统计请到「投递管理」查看」，保留指路。
- **投递管理顶部新增 6 张状态卡**：全部投递 / 待处理 / 初筛通过 / 面试中 / 已录用 / 已拒绝，**卡片本身就是筛选器**，点哪张看哪一类，选中态用淡橙描边 + 淡橙数字。原来的那排小页签删除（同一件事两套控件）。
- **新增「按职位细分」表**：一行一个职位，列为 全部 / 待处理 / 初筛通过 / 面试中 / 已录用 / 已拒绝，首行是「全部职位」合计；**点某一行 = 只看该职位的投递**。没有投递的职位也铺一行 0，避免「这个职位是不是没人投」的疑问。原来的「职位筛选下拉」删除，改由这张表承担（也是同一件事两套控件）。
- **接口合并**：`GET /api/hr/applications` 一次返回 `stats`（全局状态数）和 `job_stats`（职位 × 状态），用一次 `groupBy(['job_id','status'])` 算完再在内存里摊到各职位，页面不用为了顶部数字再拉一次 `/hr/overview`；筛选时不带 job/status 条件，所以数字始终是全局口径，切筛选不跳。
- **「在招职位」不作为卡片**：它统计的是职位数不是投递数，放进投递管理容易和职位筛选混。职位数在细分表标题「3 个职位」和工作台「本企业职位 3 个」都有。
- 列表工具栏简化为：当前筛选（职位 / 状态两个灰标签 + 清空）+ 排序。

### 2026-11-23（删掉状态卡，细分表接管筛选）
- **删除顶部 6 张状态卡**：它和细分表首行「全部职位」是同一组数字（全部 / 待处理 / 初筛通过…），页面上并排两块，看哪个都要先对一眼是不是一样。现在数字只在细分表里出现一次。

### 2026-11-23（投递管理拆成「职位表 → 投递列表」两页）
- **两个表格不再同屏**：上面是职位汇总、下面是该职位的候选人，一块屏幕里两套表头容易串行，也说不清「下面的表到底在看谁」。现在 `/hr/applications` 只有职位表，点一行才进 `/hr/applications/:jobId` 看该职位的投递列表；`/hr/applications/all` 是跨职位的全部投递。
- **职位表回归「只读汇总 + 入口」**：数字不再兼作状态筛选，改成整行可点（`<Link>` + `after:absolute` 铺满行），行尾加箭头；职位名下补一行「城市 · 在招/已下线」，避免只看标题分不清。

- **接口**：新增 `GET /api/hr/breakdown`（只返回 `jobs / job_stats / stats`，不带明细），实现抽成 `loadBreakdown()` 与 `/hr/applications` 共用，两个页面的数字同源；列表接口返回结构不变，明细页的状态胶囊直接用其中的 `job_stats`。
- 路由：`/hr/applications/:jobId` 新增，`jobId=all` 表示不按职位过滤；手改 URL 指向不存在的职位时列表页提示「该职位不存在或已被删除」。
- **「返回投递管理」从小字链接改成按钮**：原来 12px 的灰字挤在标题上方，几乎看不见；现在是 15px + 边框 + 箭头图标的按钮（150×41），与右侧排序下拉同高，回退动作不用再瞄准一行小字。
- **删掉胶囊行尾的「清空状态」**：点「全部」胶囊就是清空，同一个动作没必要两个入口；空结果页里的「清空状态筛选」保留（那里没有胶囊可点）。
