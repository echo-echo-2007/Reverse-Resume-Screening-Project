## 1. 页面一：我的简历 `/my/resume`

### 1.1 入口与权限

- 顶部导航「我的简历」
- 仅 `role === 'seeker'` 可进；HR 访问显示「当前账号是 HR，该页面仅限求职者访问」
- 未登录跳 `/login`，登录后回到本页

### 1.2 布局

```
┌────────────────────────────────────────────┐
│ 我的简历                       [已完成度提示?] │
├────────────────────────────────────────────┤
│ 基本信息                                    │
│  姓名*        手机号*     邮箱               │
│ 期望城市      最高学历*                     │
├────────────────────────────────────────────┤
│ 教育背景                                    │
│  学校         毕业年份                      │
├────────────────────────────────────────────┤
│ 工作经历                                    │
│  工作年限（年）*                            │
│  工作经历（多行文本）                        │
├────────────────────────────────────────────┤
│ 自我评价                                    │
│  多行文本                                   │
├────────────────────────────────────────────┤
│                        [保存简历]（右下）    │
└────────────────────────────────────────────┘
```

### 1.3 字段清单

| # | 字段（数据库列） | 界面标签 | 控件 | 必填 | 校验规则 | 库限制 |
|---|---|---|---|---|---|---|
| 1 | `full_name` | 姓名 | 单行输入 | ✅ | 非空，≤ 64 字 | varchar(64) |
| 2 | `contact_phone` | 手机号 | 单行输入 | ✅ | `1[3-9]` 开头共 11 位 | varchar(20) |
| 3 | `contact_email` | 邮箱 | 单行输入 | ❌ | 若填则需含 `@` 与域名 | varchar(255) |
| 4 | `expected_city_code` + `expected_city_name` | 期望城市 | 下拉（现有 8 个城市） | ❌ | 选中同时写 code 与 name；清空则两者都置空 | char(6) / varchar(64) |
| 5 | `highest_education_level` | 最高学历 | 下拉（高中及以下/大专/本科/硕士/博士 → 1–5） | ✅ | 1–5 整数 | unsigned tinyint |
| 6 | `school` | 学校 | 单行输入 | ❌ | ≤ 128 字 | varchar(128) |
| 7 | `graduation_year` | 毕业年份 | 数字输入（4 位） | ❌ | 1900 ≤ 年 ≤ 当前年+10；空则存 null | unsigned smallint |
| 8 | `work_months` | 工作年限 | 数字输入（只填年） | ✅ | ≥ 0 整数（界面单位：年）；提交时 ×12 换成月存库 | unsigned int |
| 9 | `work_experience` | 工作经历 | 多行文本（6 行） | ❌ | 无硬限制 | mediumtext |
| 10 | `self_evaluation` | 自我评价 | 多行文本（4 行） | ❌ | 无硬限制 | text |

> 口径说明：界面只让用户填「年」，保存时前端换算成月写入 `work_months`（填 2 年 → 存 24）。这样与 `jobs.min_experience_months`（月）口径一致，后端初筛逻辑一行都不用改。

### 1.4 交互细节

| 场景 | 行为 |
|---|---|
| 进入页面、尚无简历（后端 404） | 不报错，展示空表单；姓名、手机号用登录账号的 `name` / `phone` 预填 |
| 进入页面、已有简历（200） | 表单填入现有值，标题旁显示「上次保存：2026-11-17 21:30」 |
| 点保存 | 校验 → 调 `PUT /api/resume`（**整份提交**）→ 成功提示「简历已保存」→ 按钮短暂禁用防重复提交 |
| 校验不通过 | 出错字段下方红字说明，不发起请求 |
| 保存失败 | 表单顶部红色提示条显示后端 `error` 文案，已填内容不丢 |
| 离开页面有未保存修改 | 弹「有未保存的修改，确定离开？」拦截 |

**关键约束：`PUT /api/resume` 是全量覆盖。** 只传部分字段会把未传字段写成 null，所以前端必须始终提交全部 10 个字段（哪怕为空也要显式传 null）。这是本期最容易出错的地方。

## 2. 页面二：我的投递 `/my/applications`

### 2.1 入口与权限

- 顶部导航「我的投递」；仅求职者可进，规则同上
- 与「我的简历」的关系：没填简历也能进，但列表为空时提示「先去填一份简历」

### 2.2 布局（卡片列表）

按卡片列表（每行一条），从上到下按投递时间倒序：

```
┌──────────────────────────────────────────────────┐
│ 前端工程师                        [面试中]        │
│ 星辰科技有限公司 · 上海                            │
│ 15K-25K                            11-17 21:30 投递│
└──────────────────────────────────────────────────┘
```

被拒绝的额外多一行：

```
│ 拒绝原因：系统初筛 · 经验不足（需要 24 个月，当前 12 个月）│
```

### 2.3 每条展示的字段

| 展示项 | 数据来源 | 说明 |
|---|---|---|
| 职位标题 | `jobs.title` | 点击整卡跳 `/jobs/:id` |
| 企业名 | `jobs.companies.name` | |
| 城市 | `jobs.city_name` | 为空显示「不限」 |
| 薪资 | `jobs.salary_min/max` | 复用 `formatSalary`，橙色 |
| 投递时间 | `applied_at` | 格式 `MM-DD HH:mm` |
| 状态标签 | `status` | 见下表 |
| 拒绝原因 | `reject_stage` + `reject_reason` + `reject_note` | 仅 `rejected` 显示 |
| 职位是否仍在招 | `jobs.status` | 非 `published` 时标灰「已下线」 |

### 2.4 状态标签

| status | 文案 | 颜色 |
|---|---|---|
| `pending` | 待初筛 | 灰 |
| `screened` | 初筛通过 | 天蓝 |
| `interview` | 面试中 | 靛蓝 |
| `hired` | 已录用 | 绿 |
| `rejected` | 已拒绝 | 酒红 |

映射已存在于 `constants.js` 的 `STATUS_LABEL` / `STATUS_STYLE`，直接复用。

### 2.5 拒绝原因的展示规则

| 字段 | 取值 → 文案 |
|---|---|
| `reject_stage` | `sql` → 系统初筛；`manual` → HR 操作 |
| `reject_reason` | `education` 学历不符 / `experience` 经验不足 / `city` 城市不符 / `other` 其他 |
| `reject_note` | 原样显示为括号补充，例如「学历不满足：职位要求 3，简历 2」 |

三者任一为空时跳过对应片段，不显示「null」。

### 2.6 空状态与加载态

| 场景 | 展示 |
|---|---|
| 加载中 | 「加载中…」居中 |
| 0 条投递 | 「还没有投递记录」+ 按钮「去职位广场看看」 |
| 接口失败 | 红色提示条 + 「重试」按钮 |

## 3. 验收清单

- [ ] 新求职者注册 → 进「我的简历」看到空表单，姓名/手机号已预填
- [ ] 只填姓名+手机号+学历 → 能保存成功（其余字段为空）
- [ ] 刷新页面 → 数据回填一致
- [ ] 修改其中一项再保存 → 其他字段不被清空（验证全量提交做对了）
- [ ] 手机号填 10 位、学历不选 → 前端拦住并提示，不发请求
- [ ] 未填简历时进「我的投递」→ 空状态正常
- [ ] 投递 1 个职位 → 列表出现 1 条，状态「待初筛」
- [ ] HR 初筛后刷新 → 状态变「初筛通过」或「已拒绝」+ 拒绝原因
- [ ] HR 账号直接访问 `/my/resume` → 提示仅限求职者
- [ ] 接口挂掉时（关后端）→ 显示「网络连接失败」而不是白屏

## 4. 已定方案

**问题 1：工作年限怎么输入？**
- 只留一个「工作年限（年）」输入框，由用户自己填就业时长；提交时 ×12 换成月写入 `work_months`

**问题 2：有未保存修改时离开页面，要不要拦一下？**
- A 拦，弹「有未保存的修改，确定离开？」（多点代码，但防误触）

**问题 3：「我的投递」用卡片列表还是表格？**
- A（推荐）卡片列表：手机端也能看，和职位广场风格统一

**问题 4：要不要「撤回投递」功能？**
- 建议：本期不做，V1 不需要

**问题 5：期望城市只有 8 个选项（上海/北京/深圳/广州/杭州/南京/成都/武汉），够吗？**
- A 够，就用现有 8 个

**问题 6：保存简历后怎么反馈？**
- A（推荐）按钮旁出现绿色「已保存」，2 秒后自动消失，停留在本页
